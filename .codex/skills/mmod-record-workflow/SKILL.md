# Mmod Record 工作流

## 每轮入口

1. 读取本 skill。
2. 读取根 `AGENTS.md`、`README.md` 以及本次任务直接相关的设计、计划、代码和验证说明。
3. 判断 Direct、Relay 或 Discovery。
4. 核对当前分支、`git status --short`、相关 diff、任务白名单和用户已有修改后再行动。

禁止只凭对话记忆实现。禁止自行 branch、worktree、stash、reset、clean 或覆盖用户修改。提交、push、发布和外部操作仅按用户明确授权与项目规则执行。

## 协作模式

- **Direct**：用户要求当前 AI 直接修改或修复；完成实现、自审、适度验证和回执。
- **Relay**：用户要求执行计划、完整提示词或交给其他 AI；使用下述 Standard/Parallel Relay。
- **Discovery**：产品目标或会改变架构的关键选择尚未确定；一次只确认一个真正阻塞的问题，确认后转 Direct 或 Relay。

不得仅因任务大、文件多、上下文有限或普通 Bug 而选择并行。

## Standard Relay（默认）

用户只要求计划或提示词时，输出一份完整计划和一份全量提示词，由一个执行 AI 连续完成实现、Review、验证、修复、文档同步、获授权的提交和最终回执。禁止自动升级并行，禁止拆成需要用户反复搬运的逐阶段提示词。

计划必须包含：

- 当前事实、唯一方向和非目标；
- 精确读写范围、受保护修改与测试授权；
- 数据/状态/错误契约和禁止捷径；
- 按顺序、可独立验收的 Markdown 复选项；
- 最小验收矩阵、必要静态/构建/运行证据；
- Git/发布权限与防震荡停止协议。

提示词第一行必须引用本 skill 的绝对路径和计划绝对路径，内容填入真实仓库、范围、命令和状态，不留用户填写的占位符，也不要求“完成本阶段后等待下一提示词”。

## Parallel Relay（仅显式指定）

只有用户明确要求并行、多 AI 或拆成互不影响的小计划时，读取 [references/parallel-relay.md](references/parallel-relay.md)。必须先证明至少两个 ready 节点无依赖且写集互斥，并冻结共享契约；否则退回 Standard Relay。最终必须由一个协调者统一 Review、验证、修复、文档同步和 Git 收口。

## 计划进度与生命周期

- 每完成一项并取得证据后，立即勾选该项并更新计划开头的“当前执行状态”，再开始下一项；部分完成不得勾选。
- 上下文压缩或换执行 AI 后，先重读计划、status 和相关 diff，从第一个未勾选项继续。计划文件是唯一进度真相源。
- 待执行/执行中/中断待续计划与提示词放在 `docs/roadmap/plans/active/`；已完成/已取代/已取消的放在 `docs/roadmap/plans/archive/`。目录不存在时，仅在首次确有 Relay 计划时创建。
- 完成后先写齐证据、归档计划与提示词、同步有效引用，再报告完成。

## Mmod Record 工程边界

- 项目为 WPF/.NET 应用，解决方案为 `MomentumBlur.slnx`；原生 `mmod_native` 由 CMake + Visual C++ 构建。具体命令和前置条件以 `README.md` 为准。
- 修改录制链路、Native/GPU、编码、磁盘安全、性能预检或崩溃恢复时，先读取对应设计和现有状态机实现；不可逆边界必须依靠正向证据，不以“没有报错”代替成功。
- 保持任务冻结配置、Attempt/CaptureSession 隔离、故障传播、受控清理、媒体验证和原子输出等既有可靠性契约；若请求会改变这些契约，先走 Discovery/设计更新。
- 普通 WPF UI 和可逆逻辑修改优先复用现有 ViewModel、Service、Style 与 WPF UI 组件结构，不顺带重构 Native、录制状态机或数据模型。
- 保留用户工作区现有改动。只处理本任务直接相关文件，不为全绿追查无关基线失败。

## Review 与验证

默认采用实现后 Review：先实现，再逐项对照需求、相关设计和代码质量审查，修复阻断项并复审，然后运行风险匹配的现有验证。

- 普通局部 UI/逻辑：相关项目编译或最小现有检查，必要时由用户真实体验。
- 涉及 Native、录制状态机、磁盘安全、并发、持久化、跨进程或发布：读取 README/设计后运行直接相关 Smoke/构建，并明确实机、GPU、游戏或外部工具未验证项。
- 未经用户精确授权，不新增或修改测试、断言、fixture、stub、故障注入入口或测试专用生产钩子。
- 不通过降低需求、吞异常、静默 fallback、删除断言或只改探针制造通过。
- 构建成功不等于真实录制、GPU、游戏或视觉验收。

## 防震荡停止

以下任一情况发生时立即停止：

- 同一失败签名连续出现 3 次；
- 同一子系统尝试 2 种策略后通过数无净增加；
- 连续 3 次修改主要只是调常量、顺序、等待、重试或搜索上限；
- 单个命令 60 秒无新输出；
- 继续需要越过白名单、改变已批准契约、修改未授权测试或猜测外部环境。

停止后终止长进程、停止编辑、保留现场，不提交、不清理；把完成项、首个错误、尝试策略、当前文件、最后成功证据和下一步写入计划，只提出一个会改变方向的问题。禁止“最后再试一次”。

## 完成回执

只有验收成立才能报告 Pass。回执包含：结论、实际文件、Review 修复、命令与结果、真实运行/视觉证据、偏差、未验证项、Git 状态，以及在获得授权时的 commit/push 信息。
